# LIVE 最新 K 线市场环境同步修复

日期：2026-07-31（Asia/Tokyo）

## 原因

Freqtrade 在同一轮中依次分析 50 个交易对。原组合策略在分析某个交易
对时，从 DataProvider 再读取其他交易对；这批数据比当前正在分析的
最新已收盘 1H K 线慢一根。因此最新行的 `breadth`、
`market_efficiency`、BTC/ETH 四小时收益等字段为空。

一小时后这些字段虽然出现，但原入场信号已经超过 30 秒有效期，造成
Breakout 和 Grid 候选无法进入订单流程。引擎心跳、账户查询和 GUI
仍可正常显示，所以仅检查进程状态无法发现这一问题。

## 修改范围

- 只修改组合适配器的 DRY-RUN/LIVE 数据同步；
- 捕获 Freqtrade 实际传入的 50 个已收盘 K 线快照；
- 所有交易对最新时间完全一致后，按冻结公式统一计算一次市场环境；
- 对该时间点只重新分析一次，再交给 Freqtrade 检查入场；
- 任一交易对缺失或落后时不使用旧字段，当前轮禁止候选并在下一轮
  重试；
- Breakout v10F、Grid v8 的信号阈值、风险、杠杆、仓位管理与退出
  规则均未修改。

## 验收

- 自动测试：30/30 通过；
- 同步专项测试：最新字段完整、旧数据拒绝、无未来数据、公式等价、
  候选通过 `confirm_trade_entry`；
- 主网公开行情 DRY-RUN：50/50 个交易对处于同一最新已收盘 K 线，
  市场环境字段全部非空，API 启停通过，真实订单数为 0；
- 3 个月 Freqtrade 逐分钟回测：52 笔、+30,212.64U、PF 11.856、
  胜率 71.15%、逐分钟钱包最大回撤 9.69%；
- 新旧 3 个月交易账本和逐分钟钱包曲线 SHA-256 均逐字节一致，证明
  回测策略与结果未被这次 LIVE 数据适配修复改变。

LIVE 在验收后保持停止，需由用户在 GUI 中主动选择模式并启动。
